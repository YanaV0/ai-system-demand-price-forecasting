# Отчет по лабораторной работе № 3

## Реализация программного компонента системы искусственного интеллекта


### 1. Компонент и его место в архитектуре

**Компонент:** `app.service` — прикладная логика прогнозирования спроса и цен.

**Назначение:** Принимает запрос на прогноз спроса на 7–30 дней и рекомендованную цену по одному товару, вызывает модель инференса, применяет прикладные правила и формирует готовый результат. Компонент отвечает только за прикладную логику и не зависит от FastAPI или базы данных.


### 2. Место на архитектурной схеме

На архитектурной схеме реализованный компонент занимает два последовательных блока:

1. **«Инференс»** — реализован в модулях `app.preprocessing` и `app.inference` (подготовка признаков и вызов модели).

2. **«Прикладная логика»** — реализован в модуле `app.service` (функция `process_request`), где применяются бизнес-правила, fallback и проверка на аномалии.

В архитектуре ЛР №2 компонент назывался app.services.forecast. При реализации он был размещен в файле app/service.py (функция process_request), чтобы не усложнять структуру папок.


### 3. Входной и выходной контракты

**Вход — ForecastRequest:**

- `sku_id`: str (1–50 символов) — идентификатор товара

- `horizon_days`: int (7–30) — горизонт прогноза в днях

- `current_price`: float (> 0) — текущая цена товара

- `history`: list[float] (минимум 14 значений, каждое ≥ 0) — история продаж

- `promo`: bool — признак действия акции

**Выход — ForecastResult:**

- `forecast_demand`: Optional[float] — прогноз спроса (шт.)

- `recommended_price`: Optional[float] — рекомендованная цена (руб.)

- `model_version`: str — версия модели

- `stale`: bool — признак того, что использован fallback (наивный прогноз)

- `needs_human_review`: bool — нужен ли аналитик

- `review_reason`: Optional[str] — причина передачи человеку


### 4. Модель и данные

**Алгоритм:** готовая модель `LinearRegression` из `scikit-learn`, обученная заранее в `app.inference`.

*Что делает модель:*

- принимает признаки товара (цена, продажи, день недели, акция);

- возвращает число: прогноз спроса (сырой).

*Что модель не делает:*

- не прогнозирует цену;

- не оценивает уверенность;

- не проверяет адекватность прогноза;

- не принимает бизнес-решений.


### 5. Прикладные правила

Разделение ответственности реализовано в модуле `app.service` (функция `process_request`):

1. Если спрос < 0, он обрезается до 0.0.

2. Если модель недоступна или упала при инференсе — fallback: среднее значение продаж за последние 7 дней, `stale = true`, `needs_human_review = true`.

3. Если прогноз спроса аномально высокий (> 1000) — `needs_human_review = true`, `review_reason = "Аномально высокий прогноз спроса"`.

4. Рекомендованная цена на данном этапе берется из `current_price`.

- Результат: Пройден

- Вход: вызов без предварительного `load()`

- Ожидание: `stale=True`, `needs_human_review=True`, использован fallback

- Результат: Пройден


### 8. Ограничения компонента

- Модель обучена на 4 синтетических примерах. Реальная точность на «живых» данных может быть ниже.

- Модель не предсказывает цену — она берется из текущей.

- Линейная регрессия склонна к экстраполяции, что может давать отрицательные значения на больших входных данных (они обрезаются правилом до 0.0).

Изменений не потребовалось. Реализованные модули точно соответствуют блокам «Инференс» и «Прикладная логика» на схеме. При этом мы объединили этапы «Валидация» и «Предобработка» в коде (схемы Pydantic + функция `prepare_features`)
