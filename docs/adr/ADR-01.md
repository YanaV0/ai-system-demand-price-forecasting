### ADR-01: Выбор режима инференса (Synchronous REST API vs Asynchronous Message Queue)


\- **Статус:** Принято (Accepted)

\- **Контекст:** Сервис прогнозирования спроса и цен рассчитывает прогнозы на горизонт 7–30 дней для всех товаров. Расчёты требует обработки длинных временных рядов и запускаются по расписанию (раз в сутки или раз в неделю) и не требуют ответа в режиме реального времени.

\- **Рассмотренные альтернативы:**

  1\. Всё через очередь сообщений.
  2\. Пакетный расчёт по расписанию: ночью запускается задача, считает прогноз для всех товаров и кладёт результат в базу.

\- **Решение:** Второй вариант.

\- **Обоснование:** Ночью удобно считать всё сразу, когда нагрузка на серверы минимальна (при непредвиденных ситуациях можно перезагрузить сервис).

\- **Последствия:** Главные преимущества: система выдерживает большой объём товаров и при возможности можно все перезагрузить без потери данных, а сам результат можно выложить одним файлом. Но необходимо реальное время чтобы дождаться самого результата и просматривать чтобы все шло по плану.
